# Dingo ContextIR 描述语言与台词修复

源码和镜像构建以 `https://github.com/DJSaa/open-h3-ir` 的 `dingo-base` 分支为准。初始上游为 `fd031e136ae3d89147324c0d1b2aa65e838c21f5`。

## 当前语言策略

2026-10-30 按用户要求恢复官方英文描述策略：无论输入中文还是英文，模型编译后的场景、动作、运镜、环境声和音乐描述均使用英文。固定字段名、素材标签、时间戳和保留标记保持原格式。

**台词、歌词及画面文字保留原语言和原文。** 英文描述不代表英文口播；中文口播仍输出 `<d>[Chinese] 准备好了，现在开始。</d>`。可通过 `dialogue[].language` 指定台词语言。

官方依据：

- [基础模式指南](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/base-en.txt)：三个核心字段、首尾帧对齐、台词构造和声音描述。
- [全参考指南](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/ref-en.txt)：六段英文描述；对白、歌词和画面文字保留原语言。

官方接口本次中文、英文及显式要求中文输出的三种输入均返回英文描述，且都保留中文原台词。依此取消之前“中文输入输出中文描述”的适配，不回退下面的缺陷修复。

## 保留的修复

1. 提取仅写在 `intent` 中、明确由“说／口播／旁白／say”等指令引出的原台词。字幕、标牌及否定的发言指令不当作对白。支持中文弯引号和直引号。
2. 保留台词原文、标点和语言；发音语言独立于描述语言。显式指令优先，否则根据台词文字识别。模型只看到占位符，代码负责还原台词和说话人编号。
3. 补齐 saying／speaking 等英文动词形式，避免漏提取台词、误判为字幕并因“禁止字幕”返回 500。
4. 模型可能在占位符外添加 `<d>`：先去掉包住受保护占位符的模型台词包装和其中非用户内容，再由代码生成唯一的台词块。拒绝嵌套 `<d>`，防止把“用普通话说”等引导词读出来。
5. 修复轮次同样保护对白。检查漏词、错误语言及嵌套标签，错误结果不能作为合格模型编译返回。
6. 只规范化描述文本，保护 `<d>` 中原台词和带引号的画面文字。五种模式保留台词，不引入基础模式中无定义的主体标签；保留多说话人和音色引用绑定。

实现集中在 `language.py`、`prose.py`、`render.py`、`validate.py`。当前策略为 `prompts/language_policy.v2.txt`，provenance 标注 `language_policy=dingo-language-v2`。v1 提示词保留作历史版本，不再加载；中文渲染分支已移除。API 请求字段不增加。

## 确定性草稿的边界

上游确定性草稿不调用模型，不能把任意中文准确翻译成英文，因此恢复上游英文模板时仍保留原始输入指令。出现非英文源指令时，明确输出 `DINGO-draft-untranslated-input` 警告和 `provenance.draft_retains_source_language=true`。`source=draft`／`fallback_reason` 可区分模型编译失败回退；不能把它当作已完成英文翻译的 `source=written`。

模型实际写出的结果必须通过英文描述校验；中文台词及画面文字不参与该语言校验。这样既保持正常编译输出英文，也不借改变描述策略回退已有台词和 500 修复。

## 验证

```bash
.venv/bin/pytest -q
.venv/bin/h3ir controls
.venv/bin/python research/language_falsification.py
```

测试覆盖中英输入、中文和英文台词、五种生成模式、中文弯引号 HTTP 请求、英文进行时语音指令、多说话人、原文标点、英文模型编译、错误语言回退、漏词以及占位符被模型包装的情况。测试使用可控模型响应，无需 GPU；另做故障植入证明关键测试能够检出对应缺陷。

历史中文描述版本已做过真实编译和中文口播对比，记录保留。恢复英文描述后的真实验证需单独标注版本，不能直接沿用此前中文正文的验收结论。音轨验收应区分“包含原台词”和“只说原台词”；自动转写证据不能替代人工听验和画质评价。
