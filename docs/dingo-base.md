# Dingo ContextIR 语言与台词修复

后续修改和镜像构建以 `https://github.com/DJSaa/open-h3-ir` 的 `dingo-base` 分支为代码来源。初始上游版本为 `fd031e136ae3d89147324c0d1b2aa65e838c21f5`。本次只修复、测试并提交源码，不修改运行中的服务。

## 修复范围

1. **描述语言**：根据 `intent` 中引号之外的指令识别中文或英文。中文输入生成中文描述，英文输入生成英文描述。协议字段名、素材标签、时间戳和保留标记保持原格式，不翻译。
2. **台词内容与发音语言**：描述语言与台词语言独立。保留用户原台词及标点；显式的普通话／英语要求优先，否则根据台词文字识别。可继续通过 `dialogue[].language` 明确指定其他语言。
3. **仅写在 intent 中的台词**：提取“说／口播／旁白／say”等明确语音指令后的引号内容，转入结构化台词通道。字幕、标牌及否定的发言指令不当作对白。支持中文弯引号和直引号。
4. **生成与修复保护**：模型只看到台词占位符，编译器负责还原原文和说话人编号；修复轮次也保护对白内容。输出校验检查描述语言、台词原文和语言标签，缺词或错误语言不能作为合格的模型编译结果返回。
5. **中文草稿**：五种模式提供中文确定性草稿。模型输出校验失败时沿用现有显式回退机制，`source=draft` 及诊断信息可区分该结果；不能将回退当作模型编译成功。
6. **弯引号与标点**：只规范化描述文本，保护 `<d>` 中原台词和带引号的画面文字，避免保护内容被改写后触发内部校验错误。

主要实现：`language.py`（识别、保护、校验）、`localization.py`（中文草稿）、`prose.py`（模型调用与修复）、`render.py`（台词输出）。提示词策略固定在 `prompts/language_policy.v1.txt`；响应 provenance 标注 `language_policy=dingo-language-v1` 和 `description_language`。API 请求字段不增加。

## 验证

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
.venv/bin/pytest -q
.venv/bin/h3ir controls
```

新增测试覆盖中英描述与中英台词四种组合、五种生成模式、中文弯引号 HTTP 请求、多说话人、字幕与对白区分、原文标点保护、模型漏词／错误语言的校验与回退、原生中文模型响应。测试使用可控模型响应，无需 GPU。提交前另做故障植入，证明语言与台词保护测试能够检出对应缺陷。最终本地验证：1003 项通过、10 项跳过；23 个控制用例全通过；3 项故障植入检查均检出对应缺陷并恢复源码；wheel 构建及新增文件打包检查通过。

## 边界及后续验证

自动描述语言识别当前只支持中文和英文，使用文字比例规则；混合语言、较复杂的省略式台词、否定或转述句可能存在歧义。明确对白优先通过结构化 `dialogue` 提交。这里没有从参考音频识别台词。

文字与协议验证不能保证 H3 实际发音和视频质量。新镜像部署后仍需以中文口播用例验证音轨，核对“准备好了，现在开始”等原台词及发音语言；再对比编译前后视频。本次本地测试不等同于完成真实模型和视频验收。中文确定性草稿只提供基础语义保底，不等同于富语义模型编译结果。
