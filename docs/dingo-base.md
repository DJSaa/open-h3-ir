# Dingo ContextIR 描述语言与台词修复

源码和镜像构建以 `https://github.com/DJSaa/open-h3-ir` 的 `dingo-base` 分支为准。初始上游为 `fd031e136ae3d89147324c0d1b2aa65e838c21f5`。

## 当前语言策略

2026-10-30 按用户要求恢复官方英文描述策略：无论输入中文还是英文，模型编译后的场景、动作、运镜、环境声和音乐描述均使用英文。固定字段名、素材标签、时间戳和保留标记保持原格式。

**台词、歌词及画面文字保留原语言和原文。** 英文描述不代表英文口播；中文口播仍输出 `<d>[Chinese] 准备好了，现在开始。</d>`。可通过 `dialogue[].language` 指定台词语言。

官方依据：

- [基础模式指南](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/base-en.txt)：三个核心字段、首尾帧对齐、台词构造和声音描述。
- [全参考指南](https://github.com/MiniMax-AI/MiniMax-H3/blob/main/skills/h3-prompt-writing/references/ref-en.txt)：六段英文描述；对白、歌词和画面文字保留原语言。

官方接口本次中文、英文及显式要求中文输出的三种输入均返回英文描述，且都保留中文原台词。依此取消之前“中文输入输出中文描述”的适配，不回退下面的缺陷修复。

## 保留的修复

1. 提取仅写在 `intent` 中、明确由“说／口播／旁白／say”等指令引出的原台词。字幕、标牌及否定的发言指令不当作对白。支持中文弯引号和直引号。
2. 保留台词原文、标点和语言；发音语言独立于描述语言。显式指令优先，否则根据台词文字识别。模型只看到占位符，代码负责还原台词和说话人编号。
3. 补齐 saying／speaking 等英文动词形式，避免漏提取台词、误判为字幕并因“禁止字幕”返回 500。
4. 模型可能在占位符外添加 `<d>`：先去掉包住受保护占位符的模型台词包装和其中非用户内容，再由代码生成唯一的台词块。拒绝嵌套 `<d>`，防止把“用普通话说”等引导词读出来。
5. 修复轮次同样保护对白。检查漏词、错误语言及嵌套标签，错误结果不能作为合格模型编译返回。
6. 只规范化描述文本，保护 `<d>` 中原台词和带引号的画面文字。五种模式保留台词，不引入基础模式中无定义的主体标签；保留多说话人和音色引用绑定。

实现集中在 `language.py`、`prose.py`、`render.py`、`validate.py`。当前策略为 `prompts/language_policy.v2.txt`，provenance 标注 `language_policy=dingo-language-v2`。v1 提示词保留作历史版本，不再加载；中文渲染分支已移除。API 请求字段不增加。

## 确定性草稿的边界

上游确定性草稿不调用模型，不能把任意中文准确翻译成英文，因此恢复上游英文模板时仍保留原始输入指令。出现非英文源指令时，明确输出 `DINGO-draft-untranslated-input` 警告和 `provenance.draft_retains_source_language=true`。`source=draft`／`fallback_reason` 可区分模型编译失败回退；不能把它当作已完成英文翻译的 `source=written`。

模型实际写出的结果必须通过英文描述校验；中文台词及画面文字不参与该语言校验。这样既保持正常编译输出英文，也不借改变描述策略回退已有台词和 500 修复。

## 跨镜头台词纠错（2026-11-02）

R04 业余版曾因 `D10-dialogue-line-duplicated` 连续两次纠错失败而返回 `source=draft`。原因是同一句台词的重复出现被保护成不同占位符，纠错指令又要求全部保留。跨镜头分段还会被后续机械修复错误补回整句；中文分段校验使用空格拼接，也会误报原文不一致。

现在，同一台词块共享占位符身份。纠错器可以移除重复出现，并可选择代码按原文标点提供的精确分段，在切镜两侧承接；台词本身不交给模型重写。合法分段不再被机械修复覆盖，中文片段可无空格精确拼接。缺词、乱序、重复、缺少跨镜头衔接标记等校验继续生效，原有两轮纠错上限和显式降级机制保持不变。

实现涉及 `prose.py`、`repair.py`、`validate.py`，回归见 `tests/test_dialogue_correction_tokens.py`。该修复不承诺所有输入永不降级，也不代表已解决生成视频的额外语音或场景一致性问题。实际服务验证仅编译提示词，不生成视频。


本次验收：全量测试 1034 passed、10 skipped，23 项控制样例全部通过。真实接口中 R04 业余版分别以编译 seed 7／17／29 调用，专业版以 seed 7 调用，4 次均为 `source=written`、`status=ready`、`fallback_reason=null`；台词原文、中文语言标签和两人的音色绑定均通过检查。原先失败的 seed 7 经两轮纠错后正常通过，没有增加纠错轮次上限。此次不生成视频，不据此宣称额外语音或场景一致性已解决。


## R07：动作参考与保留段修复（2026-11-03）

- 新增视频角色 `motion_reference`：只引用指定人物动作，不引入参考视频的人物、场景、镜头或声音；与 `edit_source`、`structure` 分开。接口契约版本升为 3。
- 未显式填写视频角色时，识别明确的动作限定语，如“视频只参考转头”“<Video 1>只给甲转头的动作方向”。多视频必须明确编号；显式角色优先；未识别或否定表达保留既有行为。这不是通用自然语言角色识别。
- 确定性规划、草稿、编译指令与校验共同使用解析后的角色；不以忽略 R8 校验解决降级。动作参考视频不应成为新增人物的外貌来源。
- `retention_analysis` 中不允许出现 `(S1)` 等编号，机械清理仅发生在该段；实际对白段与人物音色绑定不重新编号。
- 本地回归：1051 passed、10 skipped；23 个控制检查通过。新增测试已用故意关闭修复的方式验证会失败。现场验证结果另存本次测试报告。

R07 复测另发现 `[Shot 2] Static Shot. At 00:06.000, ...` 会触发 T4：仅将已存在的切镜时间移到标准位置，不生成新时间、不改对白。动作参考视频的定义由解析后的角色生成，避免将编译指令照抄进最终提示词。

现场验证完成：R07 原业余、专业输入各编译 3 次，6/6 written / ready，无降级。每版使用编译第 1 次结果、生成 seed 17 各出一条 15 秒视频，生成约 174 秒；两种 ASR 仅识别到指定对白。抽帧仍发现专业版桌型不符合长桌描述；音色、口型及连续动作质量须人工审核。验证产物单独保存，不随源码仓库发布。

## 台词回填与描述语言校验

回填 `{{D1}}` 等台词占位符时，由编译器统一生成说话人编号和已解析的音色引用。已解析为 `<Subject N>` 的角色不再重复输出“图1／图2”等中文输入别名；紧邻占位符的已识别说话前缀会合并为一次，保留英文语气、画外音说明、原始台词及音色绑定。无法确定的叙述不会被正则批量删除。

英文描述中残留少量中文也会触发校验，不能通过长篇英文稀释；台词 `<d>` 内容和明确描述的画面文字仍保留原文。重复的结构化说话前缀会进入已有纠错流程，纠错失败仍明确标识草稿回退。

该修复针对编译器可确认的格式缺陷。上游 [vLLM-Omni #8905](https://github.com/vllm-project/vllm-omni/issues/8905) 提示类似格式可能伴随异常语音，但格式正确不能保证模型绝不重复台词或产生额外人声；视频质量仍需实际生成和人工听辨验证。新增回归见 `tests/test_dialogue_output_format.py`。

## 独立纠错规范与对白审校

首次编译携带 H3 模式规范及版本化的对白规则（当前为 `dialogue_review.v3.txt`）。独立纠错不继承上一轮聊天上下文，因此每次都重新携带对应的 H3 规范；Ref2VA 同时包含基础指南中的对白、切镜约定。规范直接复用现有版本文件，避免另维护一份不一致的格式定义。

包含已登记台词的 write-first 请求，在首次改写后增加一次专门审校（temperature=0），检查重复说话前缀、音色绑定与跨镜头续说。台词以不透明占位符交给模型，附语言、长度和绑定信息；原文由程序恢复。保持调用方明确要求的时间与动作；仅允许调整模型自行安排、与短句连续发声不匹配的时序。

审校后仍执行完整校验，检查原台词、额外语音内容和绑定；最多沿用原有两轮纠错，失败明确回退，Gateway 继续拒绝降级结果。`provenance.dialogue_review`、`correction_rules` 与 `timings.dialogue_review_s` 记录是否审校和耗时。审校不是视频质量保证，仍须以生成视频验证。仅在原始 `intent` 中包含 `<d>` 而未被登记为 `dialogue` 的既有输入解析缺口，不由本次审校流程替代修复。


对白审校 v2：修正“无机械错误就不改”的矛盾指令。模型先检查每句台词在哪个镜头结束，再修正无剩余台词却要求继续说的安排；用户指定的动作和时间保持不变，模型自行编排的镜头和时间允许调整。机械纠错仍提供完整规则和台词分段占位符；发生纠错且通过校验后，再进行一次语义复查并重新校验，失败显式返回原有降级标记，不做无限重试。该机制不保证视频语音绝对遵循，须结合生成视频验证。

台词占位符身份以原始台词为准，所有独立审校和纠错均携带整句及标点分段的稳定对应关系。输入已经拆成跨镜头片段时，原始整句也不能丢失对应关系；避免原始整句占位符被误插回第一段，再与后半段重复。台词文字仍不交给模型改写。


测试部署将编译服务与推理引擎分开：ContextIR 使用独立 CPU Pod，通过内部 HTTP Service 调用常驻 Qwen。应用入口 Service 地址保持不变，仅选择新的编译 Pod。后续源码补丁仅更新 CPU 编译 Deployment，不滚动重启承载模型的 Deployment。素材和缓存使用测试共享卷中的独立状态子目录，避免两套服务并发维护同一状态。切换前验证健康、接口契约和素材上传，切换后确认实际请求到达新服务并核对模型容器未重启。


对白审校 v3 进一步约束跨镜头说明的位置：前半句的 `</d> <scenetrans>` 后不追加英文续说说明；在后一镜头中，将说明放到连接标记和后半句台词之前。保持跨镜头语义、说话人、原台词及用户指定时间不变。该调整来自 R04 专业版同参数对照：原布局出现额外语音，删除末尾说明或仅移动同一句说明后，两路转写未识别到额外台词。这是样本级证据，不保证生成模型对所有输入都严格遵循；仍需检查重新编译后的实际视频。

部署后的实际 Gateway 入口复核使用相同原始专业版请求、素材和视频参数；重新编译未降级，seed17视频的两种语音转写均仅识别到指定台词。保留失败原片、两项手工单变量对照、独立编译验证及实际入口验证，区分定位证据和服务验收；不将本次通过外推为所有种子和输入的保证。
